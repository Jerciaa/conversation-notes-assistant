4. How Everything Works Together End-to-End & Data Retention Lifecycle
•	Authentication & Patient Context Setup (R9, R14, R16): A provider logs into the React web app, receiving a secure JWT session token from the Node.js/Express backend. Express query middleware automatically filters every MongoDB query by the logged-in provider's ID so clinicians can only view their own visits. The provider selects a synthetic patient from MongoDB.
•	Explicit Consent Lock & In-Memory Audio Capture (R1, R3): Before any microphone access is allowed, the patient must grant explicit consent for that specific visit. Once confirmed, the React client captures microphone audio in browser RAM and transmits encrypted chunks over HTTPS/WSS to the Node.js server. Raw audio is never saved to browser storage, server disks, MongoDB, or logs.
•	Instant Consent Withdrawal (R2, R8): If the patient withdraws consent at any point, recording halts immediately, all audio buffers in RAM are wiped, and Node.js executes an atomic delete in MongoDB to permanently erase any captured transcript or draft note for that visit. To satisfy auditability without retaining visit data, only a non-clinical CONSENT_WITHDRAWN_PURGED timestamp and visit ID remain in the searchable audit_logs collection.
•	Speaker-Labeled Transcription via Deepgram Nova-3 (R4, R12): When the consultation ends or pauses, the Node.js server passes the in-memory audio buffer directly to the Deepgram Nova-3 API with diarize=true and utterances=true, then immediately zeroes out and discards the audio buffer from RAM. Deepgram returns a clean transcript distinguishing Speaker 1 and Speaker 2 in 1.5 seconds.
•	Grounded SOAP Note Generation via Claude Haiku 5.5 (R5, R6, R10): Node.js sends the diarized transcript, the selected specialty template, and the patient's MongoDB medical record to Claude Haiku 5.5 strictly from the server. Claude identifies which speaker is the clinician and which is the patient, maps the conversation into Subjective, Objective, Assessment, and Plan sections, and flags any ambiguous details or conflicts with the patient record using visible [VERIFY] badges so nothing unstated is presented as fact.
•	Provider Review, Fallback Resilience & Analytics (R7, R8, R11, R15): The draft SOAP note appears in the React review screen—nothing is saved as final until the provider edits and approves or rejects it. If either Deepgram or Claude experiences an outage or rate limit, the server automatically falls back to an editable manual SOAP form pre-filled with any available transcript so the provider is never blocked. Every view, edit, approval, and rejection is recorded in MongoDB's searchable audit_logs collection, while turnaround time, token cost, and acceptance rates populate the team analytics view.
•	Explicit Data Retention Lifetimes:
o	Raw Audio: 0 seconds (held strictly in volatile RAM during capture/transcription and zeroed out immediately afterward).
o	In-Progress Draft Transcript: Retained temporarily in MongoDB only while the visit is active or awaiting provider review; permanently deleted immediately upon consent withdrawal or rejection.
o	Approved SOAP Notes & Audit Logs: Retained in encrypted MongoDB collections for clinical record-keeping and compliance search (R8, R10).

8. Conclusion
This architecture balances strict clinical safety with maximum technical and financial efficiency. By uniting a lightweight Node.js and React stack with MongoDB Atlas, Deepgram Nova-3's fast speaker-separated transcription, and Claude Haiku 5.5's grounded note generation, the system delivers accurate SOAP notes well within the 90-second target while eliminating raw audio storage. Relying on zero-card free developer tiers and prompt caching keeps build expenses near zero and pilot operational costs to just a few paise per note—proving that a lean, well-structured design can save clinicians 15 to 30 minutes per visit without compromising privacy, auditability, or scalability.
